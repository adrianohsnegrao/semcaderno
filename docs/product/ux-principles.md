# UX Principles

## Language

The interface must use everyday Brazilian Portuguese. It should sound like a clear business notebook, not an accounting system.

Preferred terms:

- "Quem está devendo" instead of "Contas a receber".
- "Quanto entrou" instead of "Receita bruta".
- "Quanto saiu" instead of "Despesas operacionais".
- "Quanto sobrou este mês" instead of "Resultado líquido" or "DRE".
- "Venda paga" instead of "Receita liquidada".
- "Venda fiada" or "Venda não paga" instead of technical receivable language, subject to user validation.

## Interaction Principles

- Common operations should require very few steps.
- Important numbers should be easy to read at a glance.
- Forms should ask only for information required for the task.
- The product should make the next obvious action visible.
- Destructive or financial changes should require clear confirmation.
- Error messages should explain what the user can do next.
- Reports should answer questions, not just display charts.

## Accessibility and Ease of Use

- Prefer readable text, strong contrast, clear labels, and predictable navigation.
- Avoid relying only on color to communicate status.
- Make touch targets practical for mobile and counter use.
- Keep layouts responsive for merchants who use phones or tablets.
- Avoid dense settings screens in the MVP.

## Visual Direction

The visual design should be clean and calm, but not overly polished at the expense of clarity. The interface should feel trustworthy and useful for daily work.

Visual sophistication is secondary to:

- Readability.
- Speed.
- Error prevention.
- Clear feedback after recording sales, expenses, and payments.

## Report Design

Reports should be framed around practical questions:

- "Quanto entrou hoje?"
- "Quanto saiu este mês?"
- "Quanto sobrou este mês?"
- "Quem está devendo?"
- "Quais clientes pagaram recentemente?"

Charts may be useful later, but the MVP should prioritize clear totals, lists, and explanations in plain language.

## Content Boundaries

Do not introduce ERP, accounting, tax, or enterprise terminology in the UI unless a specification explains why simpler language is insufficient.
